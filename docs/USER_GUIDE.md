# LangTextFlow 사용자 가이드

LangTextFlow는 말하는 내용을 실시간 자막으로 만들고, 필요한 언어로 번역해 청중의 휴대폰·프로젝터·OBS 화면에 전달하는 앱입니다.

이 문서는 개발자가 아닌 사용자를 기준으로 설명합니다.

## 가장 간단한 사용 순서

1. LangTextFlow를 실행합니다.
2. **마이크**를 선택합니다.
3. 발표자가 말할 **원본 언어**를 선택합니다.
4. 청중에게 보여줄 **번역 언어**를 하나 이상 선택합니다.
5. 사전 점검에서 문제가 없는지 확인합니다.
6. **세션 시작**을 누릅니다.
7. 청중에게 QR 코드를 보여주거나 Projector/OBS 화면을 엽니다.
8. 행사가 끝나면 **세션 종료**를 누릅니다.
9. History에서 기록을 확인하고 SRT/WebVTT/TXT/JSON으로 내보낼 수 있습니다.

## 처음 실행했을 때

첫 실행에서는 LangTextFlow가 컴퓨터와 AI 실행 환경을 확인합니다.

- 마이크를 사용할 수 있는지
- 음성 인식 엔진을 사용할 수 있는지
- 번역 엔진이 준비됐는지
- 필요한 로컬 모델이 있는지

문제가 있으면 가능한 경우 앱 안에서 설치·준비·재시도를 안내합니다. 고급 엔진 설정은 일반적인 사용에서는 변경하지 않아도 됩니다.

## 언어 설정

### 원본 언어

발표자가 실제로 말하는 언어입니다. 예를 들어 한국어 설교라면 **한국어**를 선택합니다.

### 번역 언어

청중에게 제공할 언어입니다. 여러 언어를 동시에 선택할 수 있습니다.

예:

- 발표자: 한국어
- 청중 A: English
- 청중 B: 日本語

하나의 음성을 인식한 뒤 각 대상 언어로 번역합니다.

## 자막 정확도를 높이는 방법

### Hotwords

사람 이름, 지명, 회사명처럼 음성 인식이 자주 틀리는 단어를 미리 알려줄 수 있습니다.

### Glossary

전문 용어와 원하는 번역을 등록할 수 있습니다. 교회·학회·기업 행사처럼 특정 용어가 반복되는 환경에서 유용합니다.

### Reference document

TXT, Markdown, PDF, DOCX 자료를 추가하면 발표 맥락을 자막 교정과 번역에 참고할 수 있습니다.

> 중요한 원문을 임의로 바꾸지 않도록 LangTextFlow의 교정 단계는 보수적으로 동작하도록 설계되어 있습니다.

## 청중에게 자막 보여주기

### Audience

같은 네트워크에 있는 청중이 QR 코드 또는 참가 주소로 접속해 자신의 기기에서 자막을 볼 수 있습니다. 청중 화면에는 운영자 설정이 노출되지 않습니다.

### Projector

행사장 스크린이나 프로젝터에 자막을 크게 보여줄 때 사용합니다.

### OBS

라이브 스트리밍이나 영상 제작에서 자막 소스로 사용할 수 있습니다.

표시 글꼴 크기, 최대 줄 수, 원문 병기, 정렬 등은 Display Profile에서 조정합니다.

## 세션 기록

세션을 종료해도 기록은 로컬 SQLite 데이터베이스에 보관됩니다.

History에서 다음 작업을 할 수 있습니다.

- 이전 세션 확인
- 제목/메모 수정
- 번역 결과 확인
- SRT 내보내기
- WebVTT 내보내기
- TXT 내보내기
- JSON 내보내기

## 어떤 AI 구성을 사용해야 하나요?

처음에는 **Auto**를 권장합니다.

Auto는 준비된 경우 VibeVoice Streaming을 우선 사용하고, 문제가 생기면 faster-whisper로 전환하도록 설계되어 있습니다.

번역은 로컬 Ollama 또는 OpenAI-compatible provider를 사용할 수 있습니다. 개인정보나 네트워크 의존성을 줄이고 싶다면 로컬 구성을 선택하는 것이 적합합니다.

## 문제가 생겼을 때

먼저 앱의 **Preflight / 준비 상태**를 확인하십시오.

대표적인 원인은 다음과 같습니다.

| 증상 | 먼저 확인할 것 |
|---|---|
| 소리가 들어오지 않음 | OS 마이크 권한, 선택된 마이크 |
| 자막이 시작되지 않음 | ASR 준비 상태와 모델 |
| 번역만 나오지 않음 | 번역 provider와 target language |
| 로컬 번역 연결 실패 | Ollama 실행/모델 준비 상태 |
| 청중이 접속하지 못함 | 같은 네트워크인지, join 정보가 맞는지 |
| 자막이 늦음 | 시스템 부하, 모델 크기, queue/latency telemetry |

자세한 복구 방법은 [Troubleshooting](TROUBLESHOOTING.md)을 참조하십시오.

## 개인정보와 네트워크

LangTextFlow는 local-first를 기본 방향으로 설계합니다.

- 운영자 제어와 오디오 입력은 로컬 PC 경계에서 보호합니다.
- LAN 청중은 읽기 전용 Audience 경로만 사용합니다.
- 클라우드 provider는 사용자가 명시적으로 선택할 때만 사용합니다.
- 세션 기록은 기본적으로 로컬 SQLite에 저장됩니다.

외부 provider를 사용할 경우 해당 provider의 데이터 처리 정책도 적용될 수 있습니다.

## 현재 버전에서 알아둘 점

현재 프로젝트는 실제 현장 검증 이전 단계입니다. 자동 테스트와 장시간 입력용 harness가 존재하더라도 실제 행사장에서의 음향 환경, 장비 조합, 번역 품질은 별도로 검증해야 합니다.

기술적인 상세 내용은 [문서 인덱스](README.md), 개발 구조는 [Architecture](ARCHITECTURE.md)를 참조하십시오.
